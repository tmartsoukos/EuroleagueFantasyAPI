# Web εφαρμογή (PWA)

Εφαρμογή για τη χρήση του API χωρίς curl ή Swagger. Σερβίρεται από το ίδιο το FastAPI στο `/app/` (στο Render: <https://euroleague-fantasy-api.onrender.com/app/>, τοπικά: <http://127.0.0.1:8000/app/>). Το `GET /` ανακατευθύνει εκεί.

## 1. Γιατί μέσα στο API

- **Ίδιο origin:** ο browser καλεί το API χωρίς CORS (το API δεν έχει CORS).
- **Ένα deploy:** το υπάρχον CI και το Render hook ανεβάζουν API και εφαρμογή μαζί, και το smoke check του CI ελέγχει το ίδιο commit.
- **Χωρίς build:** HTML, CSS και ES modules, καμία εξάρτηση και κανένα CDN. Τα αρχεία είναι στο `src/elfantasy/web/` και ακολουθούν το `pip install --no-deps .` του Render (`package-data` στο `pyproject.toml`).

## 2. Οθόνες

| Διαδρομή | Οθόνη | Τι κάνει |
|---|---|---|
| `#/rankings` | Κατάταξη | Ένα αίτημα `GET /rankings?limit=500&include_unavailable=true` για όλους τους ενεργούς παίκτες. Φίλτρο ομάδας, αναζήτηση ονόματος (όπως στο API: χωρίς τόνους και στίξη), εμφάνιση των `out`, κουμπί «+» για το ρόστερ |
| `#/player` και `#/player/P003469` | Παίκτης | Αναζήτηση με `GET /players`, πρόβλεψη με `GET /predict/{id}?include_features=true`: fantasy, PIR, επόμενος αγώνας (ώρα της συσκευής), διαθεσιμότητα, σημειώσεις στα ελληνικά, features |
| `#/lineup` | Ρόστερ | 10 παίκτες: 5 βασικοί, έκτος, 4 πάγκος. Captain ×2 (μόνο από την πεντάδα), πάγκος ×0,5, όριο 6 ανά ομάδα. Συνολική πρόβλεψη, αυτόματη συμπλήρωση, προειδοποιήσεις για `out` και `doubtful` |
| `#/admin` | Διαχείριση | Σύνδεση με `ADMIN_API_KEY`, καταχώρηση και αφαίρεση διαθεσιμότητας, `POST /admin/refresh` |

Η κεφαλίδα δείχνει την κατάσταση από το `GET /health` (Online ή εκτός λειτουργίας, με το data cutoff και, στο tooltip, την έκδοση και το MAE του μοντέλου).

## 3. Ρόστερ

Κανόνες από το `FANTASY_RULES.md` (ενότητα 5):

- Πεντάδα και έκτος παίκτης 100%, πάγκος 50%, captain ×2 από την πεντάδα, έως 6 παίκτες από την ίδια ομάδα.
- Το σύνολο είναι `Σ βάρος × predicted_fantasy`. Παίκτης `out` μετράει 0 (το API επιστρέφει ήδη 0).
- **Αυτόματη συμπλήρωση:** άπληστη επιλογή κατά φθίνον `predicted_fantasy` με όριο ομάδας, χωρίς παίκτες `out`, και ανάθεση στα βάρη με φθίνουσα σειρά (captain ο καλύτερος). Επειδή το όριο ανά ομάδα είναι περιορισμός τύπου matroid και τα βάρη ταξινομούνται, αυτό δίνει το μέγιστο σύνολο για τους περιορισμούς που ελέγχονται.
- Η λογική είναι σε καθαρό module (`lineup.js`) και δοκιμάζεται με `node --test`.
- Το ρόστερ αποθηκεύεται στο `localStorage` της συσκευής. Μετά από κάθε φόρτωση της κατάταξης καθαρίζεται: άγνωστοι ή διπλοί παίκτες φεύγουν και ο captain πρέπει να είναι στην πεντάδα.

**Όρια:** το API δεν δίνει τιμές παικτών (το επίσημο παιχνίδι έχει 100 credits) ούτε θέσεις (2C/4F/4G) ούτε προπονητή. Αυτά **δεν ελέγχονται και δεν υπολογίζονται**· το UI το λέει ρητά. Για να προστεθούν χρειάζεται νέα πηγή δεδομένων.

## 4. Ασφάλεια

- **Κείμενα από το API** (ονόματα, `note`, `source`) μπαίνουν στο DOM μόνο ως κείμενο. Δεν υπάρχει `innerHTML` ή `eval` (το ελέγχει test στατικής ανάλυσης).
- **CSP** μέσω `<meta>`: μόνο `'self'` για script, style, εικόνες και συνδέσεις· χωρίς inline script ή style και χωρίς εξωτερικούς hosts.
- **Κλειδί διαχειριστή:** ζητείται σε πεδίο password και κρατιέται μόνο στο `sessionStorage` της καρτέλας (χάνεται με το κλείσιμο)· ποτέ σε URL, `localStorage` ή logs. Η σύνδεση ελέγχει το κλειδί με `DELETE /availability/PZZZZZZ`: ο έλεγχος κλειδιού γίνεται πρώτος, άρα σωστό κλειδί δίνει 404 (άγνωστος παίκτης, τίποτα δεν αλλάζει), λάθος 401 και κλειστό admin API 503. Ένα 401 σε οποιαδήποτε κλήση αποσυνδέει.
- **Service worker** (`/app/sw.js`, scope `/app/`): αποθηκεύει μόνο το κέλυφος της εφαρμογής (network-first). Οι απαντήσεις του API **δεν** αποθηκεύονται ποτέ.
- **Cache αρχείων:** τα στατικά αρχεία έχουν `Cache-Control: no-cache` (ο browser ρωτά με ETag κάθε φορά), ώστε μετά από deploy να μη μένουν παλιά modules.

## 5. Cold start του Render

Στο free plan η υπηρεσία κοιμάται μετά από αδράνεια και το πρώτο αίτημα μπορεί να πάρει έως ένα λεπτό. Μετά από 3,5 s χωρίς απάντηση η εφαρμογή δείχνει «Ο server ξυπνάει…», και τα `GET` ξαναδοκιμάζονται (2 φορές) σε σφάλμα δικτύου ή 502/504· timeout 90 s.

## 6. Εγκατάσταση ως εφαρμογή

Το `manifest.webmanifest` και τα εικονίδια (`icon.svg`, `icon-192.png`, `icon-512.png`) επιτρέπουν «Προσθήκη στην αρχική οθόνη» (κινητό) ή «Εγκατάσταση» (Chrome/Edge στον υπολογιστή). Απαιτείται HTTPS (το Render το δίνει) ή `localhost`.

## 7. Αρχεία

| Αρχείο | Ρόλος |
|---|---|
| `index.html`, `app.css` | Σκελετός, θέμα (φωτεινό/σκούρο με `prefers-color-scheme` και διακόπτη), mobile-first layout |
| `app.js` | Πλοήγηση με hash, κατάσταση υπηρεσίας, θέμα, service worker |
| `api.js` | Πελάτης του API: timeout, retry, ειδοποίηση cold start, μηνύματα σφαλμάτων στα ελληνικά |

| `util.js` | Δημιουργία DOM, μορφοποίηση, αναζήτηση, ονόματα, μετάφραση των `notes` |
| `view-*.js` | Οι τέσσερις οθόνες |
| `theme.js` | Εφαρμογή του αποθηκευμένου θέματος πριν από την πρώτη εμφάνιση |
| `sw.js`, `manifest.webmanifest`, `icon*` | PWA |

## 8. Δοκιμές

- `tests/integration/test_web_app.py`: σερβίρισμα και τύποι αρχείων (το `.js` ορίζεται ρητά ως `text/javascript`, γιατί στα Windows το μητρώο μπορεί να δώσει `text/plain`), ETag και 304, ύπαρξη όλων των αναφορών (HTML, imports, manifest, service worker), CSP, απουσία `innerHTML`/`eval`, το κλειδί δεν υπάρχει στα αρχεία και μένει στο `sessionStorage`, καμία εξωτερική διεύθυνση.
- `tests/web/lineup.test.mjs`: 7 tests της λογικής του ρόστερ με `node --test` (τρέχουν και από το pytest αν υπάρχει `node`, αλλιώς παραλείπονται).
- Η οπτική λειτουργία (κατάταξη, παίκτης, ρόστερ, σύνδεση και καταχώρηση διαθεσιμότητας, mobile 375 px, φωτεινό και σκούρο θέμα) ελέγχθηκε χειροκίνητα σε πραγματικό browser πάνω σε τοπικό `uvicorn`· δεν υπάρχουν αυτοματοποιημένα browser tests.

## 9. Περιορισμοί

- Μόνο ελληνικό UI. Οι μορφοποιήσεις (`el-GR`) εξαρτώνται από τη γλώσσα του browser.
- Το ρόστερ ισχύει ανά συσκευή (δεν συγχρονίζεται) και δεν ελέγχει credits και θέσεις.
- Ο διαχειριστής είναι ένας ρόλος με ένα κοινό κλειδί· δεν υπάρχουν λογαριασμοί χρηστών.
